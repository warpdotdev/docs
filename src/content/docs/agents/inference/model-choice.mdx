Choose a model for your agents, use Auto for dynamic selection, or define a [custom router](/agents/inference/custom-routers/). Models support reasoning levels and per-profile defaults.

## Available models

The `model_id` values shown below can be used when configuring models via the [{VARS.WARP_AUTOMATION_PLATFORM}](/platform/overview/) or [CLI](/agents/cli/oz-cli/).

### Auto models

| Model | `model_id` | Description |
| --- | --- | --- |
| Auto (Responsive) | `auto` | Selects the highest-quality, fastest available model. Can cost more than cost-efficient options. |
| Auto (Cost-efficient) | `auto-efficient` | Optimizes for lower inference cost while maintaining output quality. |
| Auto (Genius) | `auto-genius` | Adapts to task complexity and selects Warp's most capable model when it's worth it. Best for deep debugging, architecture decisions, and `/plan` sessions. |
| Auto (Open-weights) | `auto-open` | Routes between the best open-source models available in Warp. Optimizes for low cost and fast speed using open-weights models. |

### Custom routers

Beyond the built-in Auto models, you can define your own custom routers that automatically route each task to a concrete model based on task complexity or rules you write. Custom routers appear in the model picker alongside Auto and individual models.

Add and manage custom routers in **Settings** > **Agents** > **Warp Agent** > **Custom Routers**. See [Custom routers](/agents/inference/custom-routers/) for details on creating one.

### Model fallback

If your selected model is unavailable, Warp uses a fallback from a predefined chain with comparable quality and capabilities. Warp switches back when the selected model becomes available.

### Configuring models per Agent Profile

You can configure the base model for each [Agent Profile](/agents/capabilities/agent-profiles-permissions/), alongside the Agent's autonomy, tool access, and other permissions. The base model is also used for [Planning](/agents/capabilities/planning/).

Edit your default profile or any other profile directly in **Settings** > **Agents** > **Profiles**.

### Reviewing inference and privacy in Terminal

To use inference covered by provider ZDR, review the model and its inference source before sending sensitive content:

1. In the Warp app's prompt input, click the current model name. Choose a Warp-managed model that isn't in the [provider-retention exception list](#models-requiring-provider-retention). If you use Auto, review [automatic selection and fallback](#zero-data-retention-policies); Auto isn't a pinned model.
2. In the Warp app, open **Settings** > **Agents** > **Profiles** and review the active profile's base model. If you use a [custom router](/agents/inference/custom-routers/), review every target and its default model, not only the router's name.
3. In **Settings** > **Agents** > **Warp Agent**, review personal keys, endpoints, and connected subscriptions, and check any [team-managed configuration](/enterprise/enterprise-features/team-managed-keys-and-endpoints/). Search Settings for `API keys` to find personal inference controls. For customer-managed inference, verify provider ZDR for the specific account, model, and configuration. Review [BYOK fallback](/agents/inference/bring-your-own-api-key/#failover-and-fallback-behavior) if enabled.
4. In **Settings** > **Privacy**, toggle off **Help improve Warp** if you don't want analytics and improvement collection. Review **Send crash reports** and **Store AI conversations in the cloud** separately. The storage toggle controls [personal Terminal conversation sync](/agents/local-agents/cloud-conversations/), not factory run storage.

Before sending the next prompt, confirm the intended model is displayed in the input. Recheck these choices when switching profiles, models, or inference providers. For cloud factory runs, use the [factory review procedure](/factories/factory-agents/configuration/#reviewing-inference-for-provider-zdr) instead.

### Zero data retention policies

Warp's provider Zero Data Retention (ZDR) agreements cover Warp-managed inference on all plans, in both Terminal and factory runs, except for the models listed below. Provider ZDR concerns prompts and responses at the inference provider; it doesn't disable [Warp analytics or product storage](/enterprise/security-and-compliance/security-overview/#what-telemetry-does-warp-collect-and-why).

Auto selects models dynamically, and [fallback](#model-fallback) can change the model serving a request. A primary model selection isn't a complete inventory of auxiliary inference, such as Computer Use or Scorers. Review the applicable [factory configuration](/factories/factory-agents/configuration/#reviewing-inference-for-provider-zdr) as well.

#### Models requiring provider retention

Anthropic requires retention for these models, including their effort variants, for safety, abuse monitoring, and compliance:

* Claude Fable 5
* Claude Fable 5.1
* Claude Fable 5.2

These models aren't covered by provider ZDR even when **Help improve Warp** is off. For Enterprise teams, they are disabled by default and a workspace admin must enable them in the [Admin Panel](/enterprise/team-management/admin-panel/#models-settings). Don't rely on Enterprise defaults as a self-serve model restriction.

For your own keys, endpoints, subscriptions, or direct Claude Code and Codex calls, verify ZDR with the provider for your specific account, model, and configuration rather than applying Warp's agreements to that traffic.
