Warp Factories is the web experience for team development workflows organized around repositories, agents, and automations. Existing standalone cloud-agent workflows still use the {VARS.WEB_APP}, CLI, SDKs, and API references listed below.

## Current status

| Surface | Current use |
| --- | --- |
| **{VARS.WEB_APP}** | Existing standalone cloud-agent workflows have their own [web app setup and management paths](/platform/oz-web-app/). |
| **{VARS.WARP_AGENT_CLI} (`oz`)** | Use the [{VARS.WARP_AGENT_CLI} reference](/agents/cli/oz-cli/) for current `oz` commands. The `oz` and `warp` binaries have separate command interfaces. |
| **{VARS.WARP_CLI} (`warp`)** | Use the [{VARS.WARP_CLI} reference](/agents/cli/) for its supported commands. |
| SDKs | Use the current [Python and TypeScript packages](/factories/api-and-sdk/#sdks). Repository names and package names can differ. |
| **{VARS.WARP_PLATFORM_API}** | Consult the [API reference](/api) for endpoint behavior and configuration. Use [factory endpoints](/factories/factory-api/) to send work to a factory. |
| **New software factories** | Open the <a href={VARS.FACTORY_WEB_APP_URL}>{VARS.FACTORY_WEB_APP}</a> and follow the [Warp Factories quickstart](/factories/quickstart/). |

## Moving an existing workflow

Adopting a factory can involve changes to your workflow's configuration or integrations. Assess the web app, commands, and API calls you currently use before making those changes.

### Existing web app workflows

The <a href={VARS.WEB_APP_URL}>{VARS.WEB_APP}</a> and the <a href={VARS.FACTORY_WEB_APP_URL}>{VARS.FACTORY_WEB_APP}</a> have different setup paths. Review the agents, skills, environments, schedules, integrations, and credentials your workflow uses before moving it into a factory. Creating a factory is not evidence that those resources or run history have transferred.

For factory setup, see [how Warp Factories work](/factories/how-factories-work/) and the [Warp Factories quickstart](/factories/quickstart/). Contact your account team or [Warp support](/support-and-community/#contact-support) if you need help assessing an existing workflow.

### CLI functionality

Use the [{VARS.WARP_AGENT_CLI}](/agents/cli/oz-cli/) for the current `oz` command reference and the [{VARS.WARP_CLI}](/agents/cli/) for current `warp` functionality. Check the relevant reference before changing a command in a script.

### SDK packages and API

The official SDK repositories keep their existing names: [Python](https://github.com/warpdotdev/oz-sdk-python) and [TypeScript](https://github.com/warpdotdev/oz-sdk-typescript). Current packages are `warp-platform-sdk` for Python and `@warp-dot-dev/warp-platform-sdk` for TypeScript; see [SDK installation and imports](/factories/api-and-sdk/#sdks).

Use the [{VARS.WARP_PLATFORM_API} reference](/api) to check the endpoints and configuration your integration needs. To send work through a factory, use [factory endpoints](/factories/factory-api/) rather than treating a standalone agent run as the same workflow.
