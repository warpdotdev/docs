The {VARS.WEB_APP} will retire after Warp Factories reaches general availability. Existing cloud agents, integrations, schedules, API keys, and the `oz` CLI remain available today, so you don't need to migrate immediately.

The {VARS.WARP_AUTOMATION_PLATFORM} remains the shared foundation for cloud agents. Warp Factories builds on that foundation for teams that need standing workflows with named agents, work intake, review stages, and measurement.

## Choose the right entry point

* **Use the {VARS.WARP_AUTOMATION_PLATFORM}** - Configure standalone cloud agents, environments, schedules, integrations, and orchestration. Start with the [{VARS.WARP_AUTOMATION_PLATFORM} overview](/platform/overview/) or [Cloud agents overview](/platform/).
* **Warp Factories** - Use a repeatable workflow that routes work through named agents and tracks it in one place. Start with the [Warp Factories overview](/factories/) or the [factory quickstart](/factories/quickstart/).

## What stays available

Existing workflows and configuration continue to work today:

* **Cloud agents** - Continue to run from existing events, schedules, integrations, APIs, and the CLI.
* **Configuration** - Existing environments, integrations, schedules, API keys, and secrets remain available.
* **Current tools** - The {VARS.WARP_AGENT_CLI}, API and SDK, and managed self-hosting continue to support their current workflows.

## What comes next

Migration actions, compatibility dates, and replacement destinations will be documented after product mapping is finalized. Until then, continue using the workflow that fits your work today.
