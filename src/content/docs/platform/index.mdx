<span id="what-is-a-cloud-agent-run" />

Cloud agents execute a request away from your laptop, on Warp-hosted compute or your own infrastructure. For example, an agent can investigate a failed build, review a pull request, or respond to an issue filed in your tracker.

## Start with Warp Factories

For a standing team workflow, start with the [Warp Factories quickstart](/factories/quickstart/). A factory brings together [agents](/factories/factory-agents/), [automations](/factories/automations/), and [evaluation](/factories/measure-and-improve/).

See [how Warp Factories work](/factories/how-factories-work/) for the task lifecycle and human review points.

## Continue a standalone workflow

To start a cloud agent directly from Warp, use the [cloud agents quickstart](/platform/quickstart/). Existing standalone runs, schedules, and integrations have their own configuration and management paths.

Already using the {VARS.WEB_APP}, {VARS.WARP_AGENT_CLI}, or SDKs? See [transitioning from Oz to Warp Factories](/platform/transitioning-from-oz/) before changing an existing workflow.

<span id="observability-and-steerability" />

## Monitor, inspect, and share cloud agent runs

For factory work, open the factory's [Runs page](/factories/factory-dashboard/#inspect-runs). For standalone workflows, use the [Agent Management Panel](/platform/managing-cloud-agents/) in Warp or the [{VARS.WEB_APP} Runs page](/platform/oz-web-app/#runs).

See [viewing cloud agent runs](/platform/viewing-cloud-agent-runs/) to inspect a transcript, share a session, or continue a standalone run.

## What cloud agents are designed for

Use [factory automations](/factories/automations/) for event-driven work and recurring maintenance in a factory. Standalone workflows have separate [integrations](/platform/integrations/) and [schedules](/platform/triggers/scheduled-agents/). [Multi-agent orchestration](/platform/orchestration/) explains how parent and child agents divide work.

## How cloud agents work

The [{VARS.WARP_AUTOMATION_PLATFORM} overview](/platform/overview/) explains the shared execution model. For factory hosting choices, see [deployment patterns](/factories/deployment-patterns/). For standalone CLI execution in your own CI or development environment, see [unmanaged execution](/platform/unmanaged-execution/).

## Using cloud agents with or without the Warp app

For standalone runs outside the Warp app, use the [{VARS.WARP_AGENT_CLI}](/agents/cli/oz-cli/), [{VARS.WEB_APP}](/platform/oz-web-app/), or [API and SDKs](/factories/api-and-sdk/). [Session sharing](/agents/local-agents/session-sharing/) and the [Agent Management Panel](/platform/managing-cloud-agents/) provide inspection paths in Warp.

Use [Handoff](/platform/handoff/) to continue work between local and cloud sessions.
