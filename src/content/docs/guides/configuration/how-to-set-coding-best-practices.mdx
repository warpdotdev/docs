Tell the agent which conventions to follow and which checks to run, then verify the result. Warp Rules are instructions, not enforcement: a formatter changes formatting, a linter checks configured patterns, and tests check the behavior they cover.

## Prerequisites

* A repository with [project Rules](/agents/capabilities/rules/#project-rules), stored in `AGENTS.md` or an existing `WARP.md`.
* The repository's documented formatter, lint, and test commands, including any setup they require.

## 1. Name a convention and its check

Open the repository's Rules file and add expectations that someone reviewing a diff can verify. For example:

```markdown title="Example project Rules"
Follow the existing TypeScript conventions in the package you change.
Document non-obvious behavior; don't add comments that repeat the code.
Read package scripts and CI configuration before choosing checks.
Run the formatter, lint, and tests relevant to the changed package.
Report exact commands and results, including any checks you couldn't run.
Leave changes for human review. Do not merge.
```

Replace broad check instructions with exact commands once you've verified them in your repository. Don't add `npm run lint` or another script unless it exists.

## 2. Try one bounded change

Give the agent a small task from your backlog. Name the files it may change and the behavior you expect. Keep the instructions to stop for review inside the prompt:

```text
Fix the failing test I attached. Keep changes to the affected implementation
and its tests. Follow the project Rules and run the relevant repository
checks. Report their exact results, and stop with the diff for my review.
Do not commit, push, or merge.
```

Inspect the diff and command output. A statement that the agent "followed best practices" isn't evidence that a check ran or that the behavior is correct.

## 3. Enforce requirements outside the prompt

Configure formatters, linters, and tests in the repository and CI. Use repository permissions, required checks, and approval rules for actions that must be restricted. [Agent Profiles and permissions](/agents/capabilities/agent-profiles-permissions/) control tool access; Rules don't grant or revoke it.

If the agent misses a check, first confirm it had the command, toolchain, and access it needed. Then clarify the instruction and repeat a small task before applying it across projects.

## Troubleshooting

**The instruction is followed inconsistently.** Replace vague phrases such as "high-quality code" with an observable criterion and a relevant check. Verify which Rules file applied.

**Checks pass but the change is wrong.** Add coverage for the missing behavior and review the acceptance criteria. Passing configured checks doesn't establish correctness outside their coverage.
