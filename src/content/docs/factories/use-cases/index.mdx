Warp Factories can automate development work like investigating bugs, preparing changes for review, and checking that an application behaves as expected. These recipes show how to configure a workflow in your existing factory, verify its results, and decide where human input is required.

Each recipe combines agents, automations, skills, integrations, and repository controls. The examples use [definitions as code](/factories/factory-as-code/) so you can review and validate changes, or adapt them to a Warp-managed factory.

## Start with one workflow

Choose one task your team can evaluate on its own, like triaging incoming issues or reviewing pull requests. Define what the factory should return and where it should stop for human input.

Before you add an automation, choose the event that should start work and check whether it's handled by an existing automation. Update that automation where appropriate, or use nonoverlapping filters when separate automations serve different purposes. See [automation matching rules](/factories/automations/#how-matching-works).

Follow the chosen recipe to configure the agents, access, and repository-specific instructions it needs. Test it on a sample issue or pull request, and review whether the output meets your expectations and respects the stopping point. Once that workflow works reliably, expand its scope or connect it to another stage.
