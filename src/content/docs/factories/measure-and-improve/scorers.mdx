A **Scorer** is an LLM judge that classifies completed runs from selected agents against criteria you write. Use it to find evidence gaps or recurring problems, then inspect the runs behind those results.

For the ["Copy link" test change](/factories/guides/testing-and-tuning-your-factory/#check-the-outputs), ask: "Does the run provide evidence that the button copies the exact displayed URL and can be activated with the keyboard?" Define classifications such as `evidence present`, `evidence missing`, and `unclear`. A screenshot alone doesn't establish either behavior.

Keep process checks separate. "Did the agent run the tests before opening a pull request?" checks whether a step happened, not whether the requested behavior works. The judge can misclassify evidence; a classification doesn't prove correctness or replace deterministic checks and human review. Compare its reasoning with your own review before relying on sampled results.

## Configure a Scorer

Create Scorers on the factory dashboard's **Scorers** page, which also holds each Scorer's results. For file-based configuration, see the [`scorers/<name>/scorer.md` syntax](/factories/factory-as-code/#scorersnamescorermd) and the examples in [`02-sdlc-issue-to-pr`](https://github.com/warpdotdev/warp-factory-examples/tree/main/examples/02-sdlc-issue-to-pr).

Configure these fields:

* **Agent(s) to evaluate** - The agents this Scorer applies to. Select at least one.
* **Judge instructions** - The criteria the judge checks for.
* **Judge model** - The model that acts as the judge.
* **Classifications** - The labels the judge can assign, each with a score.
* **Pass threshold** - The score a run needs to pass.
* **Sample rate** - The percentage of completed runs from selected agents to evaluate. For example, a 10% sample rate evaluates about one in ten runs.

With a sample rate above 0%, the Scorer automatically evaluates sampled runs after they complete and records a classification, score, and reasoning. A sample rate below 100% leaves some runs unscored.

You can also score any single run on demand, which is useful for testing new judge instructions before raising the sample rate. Scoring a run again replaces its previous result from that Scorer.
