Create a factory and take one small repository change to a pull request for human review. Use a repository whose setup and lint command you know.

## Prerequisites

* A [Warp account](https://app.warp.dev/signup) and membership in a [Warp team](/knowledge-and-collaboration/teams/).
* Team or workspace admin access, or the team-level [Warp Factories Editor role](/factories/infrastructure-and-security/#factory-roles-and-permissions).
* Available usage in your team's balance for factory runs. See [access and billing requirements](/platform/team-access-billing-and-identity/).
* Access to the repositories you want the factory to work on.

## Set up your factory

:::note
For GitHub and GitLab, an agent connected to [Factory MCP](/factories/factory-mcp/#set-up-with-your-coding-agent) can run setup. For Azure DevOps, follow the steps below.
:::

1. Open the <a href={VARS.FACTORY_WEB_APP_URL}>{VARS.FACTORY_WEB_APP}</a> and sign in. To switch teams, click your avatar, hover over the team name, and select another team.

2. Click **+** next to **Factories**.

   <figure style={{ maxWidth: "300px" }}>
   ![Factories sidebar with the + button highlighted.](../../../assets/factories/quickstart-open-setup-wizard.png)
   <figcaption>The factory setup control in the sidebar.</figcaption>
   </figure>

3. On the "Connect your code hosts" screen, select GitHub, GitLab, or Azure DevOps, then choose the organization or group to connect. For Azure DevOps, also choose a project. Click **Next**.

   <figure style={{ maxWidth: "563px" }}>
   ![Code-host connection options and the GitHub organization dropdown.](../../../assets/factories/quickstart-connect-code-forges.png)
   <figcaption>The GitHub organization dropdown in factory setup.</figcaption>
   </figure>

   If connections are restricted, involve a code-host administrator. Azure DevOps requires [administrator approval](/factories/integrations/azure-devops/#requirements); send the approval link during setup.

   For other code forges, see [Connecting other code forges to your factory](/factories/code-forges/other-code-forges/).

4. On the "Set up your factory" screen, select the repositories your factory will work on. See [sizing a factory](/factories/#sizing-a-factory).

   <figure style={{ maxWidth: "563px" }}>
   ![Factory setup with matching repositories for the search term docs.](../../../assets/factories/quickstart-connect-repo.png)
   <figcaption>A repository search during factory setup.</figcaption>
   </figure>

5. Enter a "Factory name". This also sets the default [foreman name](/factories/factory-agents/#foreman-name), the handle your team @-mentions in Slack and Linear. Click **Next**.

   <figure style={{ maxWidth: "563px" }}>
   ![Factory setup with Docs Factory entered as the name.](../../../assets/factories/quickstart-factory-details.png)
   <figcaption>The factory name and optional details during setup.</figcaption>
   </figure>

6. Choose which [agents](/factories/factory-agents/) the foreman can dispatch. Leave **Code** enabled to produce a pull request.

   <figure style={{ maxWidth: "563px" }}>
   ![Factory setup with Triage, Spec, Code, and Review enabled.](../../../assets/factories/quickstart-pick-agents.png)
   <figcaption>Default factory agents enabled during setup.</figcaption>
   </figure>

7. Optionally, connect Slack and an issue tracker. You can add either later from [Connect your factory](/factories/connect-your-factory/).

Warp creates the factory and opens its [dashboard](/factories/factory-dashboard/).

## Send your first work item

Send a request to your foreman from the {VARS.FACTORY_WEB_APP}.

1. In the web app sidebar, click **New Chat**.

2. In the dropdown below the prompt input, choose your factory.

3. Enter one small, verifiable change, then click the send arrow:

   ```text title="Example first request"
   Add a "Local development" section to README.md that summarizes the setup
   steps from CONTRIBUTING.md. Keep the change to that one file, run the
   repo's lint check, and open a pull request.
   ```

4. The foreman dispatches the agents needed for the request and posts progress where it started. In the sidebar, click **Runs** to follow the [foreman and child runs](/factories/factory-dashboard/#inspect-runs). Requests for input also appear in the **Waiting on you** status filter on [Home](/factories/factory-home/).

5. When the foreman hands back the pull request, review the changes and validation results, then merge it according to your normal process.

## Optional: adapt one instruction

Try one team-specific instruction: require the implementation agent to include the exact lint command and result in each PR description.

1. On your factory's **Agents** page, open the implementation agent. For a Warp-managed factory, click **Prompt**, edit the instruction, then click **Save**. For a GitHub-owned definition, edit the existing agent file or attached skill, review and merge the definition PR, and confirm it applies. GitHub-owned definitions require a paid plan; see [Configuring factory agents](/factories/factory-agents/configuration/).
2. Start a fresh small request through **New Chat**. Check the returned PR description against the first result. Keep the instruction only if it addresses the gap.
