import { VARS } from '@data/vars';

The `insufficient_credits` error means the billed account does not have enough eligible usage to start a cloud run. The error code is the same whether the account uses dollars or credits.

Factory runs use [shared team or workspace funding](/support-and-community/plans-and-billing/plans-pricing-refunds/#funding-factory-runs), not a member's included personal allowance. For standalone cloud runs, check the balance for the user or agent the run acts as. See [cloud run billing](/platform/team-access-billing-and-identity/#billing-for-cloud-agent-runs) for schedules, agent API key runs, and Enterprise terms.

---

## Details

* **HTTP Status:** `403 Forbidden`
* **Retryable:** No
* **Task State:** FAILED

---

## When does this occur?

This error is returned when:

* The billed user's or team's eligible balance is too low to start the run.
* Auto-reload is off or cannot replenish the balance, such as when a purchase is blocked by the team's limit.

See [Purchasing additional usage](/support-and-community/plans-and-billing/add-on-credits/) for purchases, auto-reload, and spend limits.

---

```json
{
  "type": "/factories/api-and-sdk/troubleshooting/errors/insufficient-credits/",

  "status": 403,
  "instance": "/api/v1/agent/tasks",
  "retryable": false
}
```

---

## How to resolve

1. For a factory run, open **Billing and usage** in the <a href={VARS.FACTORY_WEB_APP_URL}>{VARS.FACTORY_WEB_APP}</a> and check the shared balance. For a standalone run, open **Settings** > **Billing and usage** in the Warp app for the billed account or team.
2. [Purchase usage](/support-and-community/plans-and-billing/add-on-credits/) on an eligible plan, ask an admin to review auto-reload and the spend limit, or wait for the applicable included allowance to reset. A personal allowance reset does not fund factory runs.
3. Retry the failed operation after enough usage is available. The failed run is not retried automatically.
